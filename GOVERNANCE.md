# Governance

## Stewardship

Still Cloud is the founding steward of the Human Index. That is an authorship and maintenance role, not a claim that Still Cloud has final authority over every question raised by the framework. Publishing the Index in the open is meant to make criticism, disagreement, and extension visible.

## Rule identifiers

HI identifiers are permanent. `HI-09` remains `HI-09`. If a rule is retired in a future major version, its number is retired with it and is never reassigned.

## Versions

The project uses semantic versioning for normative releases. **PATCH** releases correct or clarify without materially changing an adopter's obligation. **MINOR** releases add rules, normative tests, or stronger obligations while preserving existing commitments. **MAJOR** releases remove, weaken, or materially redefine an existing commitment. Pre-release identifiers such as `1.0.0-draft.1` are drafts and are not stable adoption targets.

## Proposing changes

Normative changes should be proposed in public with the failure mode being addressed, the exact text proposed, concrete examples, foreseeable costs or tradeoffs, and alternatives considered. After v1.0.0, new rules and major normative changes should ordinarily remain open for at least fourteen days of public comment before release.

## Frozen releases

A stable release receives a Git tag, GitHub Release, snapshot under `versions/`, and permanent web route. Stable text is not silently rewritten. Corrections produce a new version.

## Conflicts of interest

Revenue, partnerships, or product pressure do not create an exception to an HI rule. If a steward believes a rule must change, the change should happen through the same public version process rather than through an unpublished product exception.
